03 / 文献检索

提出一个问题，

01 / 产品功能

从一句话需求，走到有理由的推荐。

Agent 负责理解问题、收集候选与筛选排序，把判断依据展示出来。推荐列表、助手回答与界面卡片始终使用同一份结果。

01 / 需求拆解

问题拆解

把自然语言需求转成可执行的检索目标：消解指代、翻译术语、生成检索式，只从用户要求中提取年份等条件。

02 / 多源检索

多源论文检索

从 arXiv 与 Semantic Scholar 取得候选，统一字段、超时重试、跨来源去重；一个来源失败时保留另一个来源的结果。

03 / 结果筛选

重排序与筛选

大模型根据标题与摘要，针对完整检索目标评分排序并给出理由；只有少量合格候选时如实返回，不拿无关论文凑数。

04 / 多轮检索

多轮追问与补搜

“是找不到吗”根据已有结果直接解释；“继续找”恢复原主题，换检索式或翻页再筛选，默认最多补搜两次。

05 / 文献库

文献库与阅读

把推荐论文加入个人工作区，支持全文解析、证据分析与单篇深入阅读，检索与分析在同一条链路里完成。

06 / 知识图谱

知识图谱与主题

基于论文关系预计算生成知识图谱与主题视图，用 G6 与 ECharts 可视化领域结构，帮助发现研究方向之间的联系。

02 / Agent 工作流

拆解、检索与排序，是可以独立验证的工具。

三个核心工具分别注册、提供清晰描述和参数，Agent 根据请求与工具返回决定下一步。工具可以单独调用、单独验证，而不是不可复用的固定步骤。

候选不等于推荐

检索工具只负责取得候选材料；是否相关由重排序工具围绕完整用户目标判断，不能因为标题命中一个词就当作相关。

04 / 检索质量与诚实性

找不到就如实说，不拿无关论文凑数。

检索链路的每一环都区分“失败”和“没有结果”，评分始终针对用户的完整目标。推荐数量、助手回答与界面卡片来自同一份结果。

2个论文数据源，跨来源合并去重
3个可独立调用验证的核心工具
5篇未指定数量时的默认推荐目标
2次结果不足时的默认补搜上限
用户要 5 篇，有足够相关结果时返回 5 篇；只有 2 篇合格就返回 2 篇并说明不足原因，不用无关论文凑数。

区分失败与无结果

请求失败、超时与“请求成功但没有结果”分别标记；一个数据源故障时，保留另一来源已取得的候选，失败信息不被包装成搜索成功。

评分针对完整目标

重排序围绕拆解后的完整检索目标打分，而不是某次改写后的宽泛检索式；没有摘要时如实标记，不编造论文内容。

推荐理由可核对

每篇推荐说明它与用户需求的联系，并标明依据是标题还是摘要；未入选候选默认折叠保留，方便回看筛选过程。

追问不重启搜索

“是找不到吗”“为什么只有两篇”根据上一轮结果与来源状态直接解释；只有明确要求继续找或换条件时才再次检索。

主题不漂移

补搜检索式可以换表述，但必须围绕同一个原始主题；“继续找”从对话上下文恢复原主题，歧义影响结果时先澄清。

结果一致性

工具的最终推荐、助手自然语言回答与前端论文卡片使用同一份推荐列表，数量与内容不会出现三种说法。

05 / 在线体验指南

用几分钟，走过一次完整的检索。

01

描述研究方向

点击上方“体验文献检索”，进入检索助手，用自然语言提出需求，例如“帮我找 5 篇关于文本向量模型的论文”。

02

观察 Agent 工作流

查看问题拆解出的主题、数量与检索式，跟踪多源检索与重排序过程，每篇推荐都带评分和理由。

03

追问与继续找

试试“是找不到吗”这类追问，Agent 会基于已有结果解释；再说“继续找”，主题保持不变、换检索式补搜。

04

探索文献库与图谱

把感兴趣的论文加入工作区，阅读全文解析与证据分析，在知识图谱与主题视图里发现方向之间的联系。
