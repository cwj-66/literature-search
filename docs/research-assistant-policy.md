# 论文研究助手：产品定位、实现和验证

2026-10-23。核心原则：**论文是研究证据的来源，不是真理本身。**


## 实际发现的问题

原工作流主要按 fact/deep/comparison/common 分类，适合决定检索策略，但不能表达用户是要理解、质疑还是探索。生成与 Judge 又偏向“每句话都必须原文直接说过”，会产生两种偏差：将作者主张视为已经成立，或者把合理但非原文原句的批判/新设想误判为无依据。

另一处真实风险是混合回答：正文出现“助手分析”，关键主张列表却只列作者陈述。只批准整份回答会漏掉分类边界。因此增加了完整回答和独立论述之间的分类检查。

## 现在的流程

理解研究意图 → 明确所需证据 → 按论文独立混合检索 → 按需展开父块 → 判断事实前提覆盖 → 生成分层研究回答 → 按论述类型复核 → 保留有依据的内容及不确定性。

| 用户任务 | 所需材料与行为 |
| --- | --- |
| 研究动机 motivation | 作者问题定义、相关工作、作者认为的不足；区分问题判断与验证结果 |
| 研究方法 method | 方法步骤、假设、设计依据与贡献；区分公开设计理由和助手解释 |
| 实验与证据 experiments | 设置、基线、指标、结果、消融；判断结果支持什么及其适用条件 |
| 批判性分析 critique | 作者主张、方法假设、实验范围和局限；允许从前提分析潜在问题 |
| 跨论文比较 comparison | 逐篇按同一维度取证，检查任务和条件是否可比，保留差异与冲突 |
| 延伸研究 exploration | 已有方法和边界作为前提，提出条件化设想、失败条件与验证方案 |

意图可以混合。例如同时追问“作者为什么研究”和“哪些判断已被验证”时，规划器可以将批判视为主意图，仍检索动机与实验。`research_intent`、`reasoning_mode` 与 `evidence_needs` 增加在原检索计划中；原 question_type/strategy 保留。较长的开放问题交由同一次规划模型理解，不仅依赖固定关键词；简单明确的事实问题仍直接检索。

覆盖检查审核**推理所需的事实前提**，不要求原论文已经实施用户提出的新组合或验证实验。摘要仍可用于有限分析，但不能冒充正文支持具体实现和实验细节。补充检索仍最多一次，且不扩大论文范围。

## 四类论述与不同的审核标准

| 类别 | 要求 | 复核通过意味着 |
| --- | --- | --- |
| `author_claim` 作者陈述 | 正确归属、真实来源，不把作者声称升级为客观定论 | 忠实呈现作者说了什么 |
| `experimental_result` 实验支持的结论 | 明确评估条件，核对报告的结果、数据、基线和指标 | 结论没有超出已报告评估范围 |
| `analysis` 助手分析 | 引用事实前提、给出 reasoning 与 uncertainty | 有前提的分析在所标明的边界内合理 |
| `hypothesis` 待验证研究设想 | 除前提、推理和不确定性外，必须有 validation 方案 | 一个有来由、可检验的设想，不是已证实效果 |

模型返回结构化 `claims`；后端使用独立 `ResearchStatement` 校验，不放宽全站论文抽取使用的 `AnalysisClaim`。缺少引用前提、分析边界或设想验证计划的条目不会因为整份回答获准而被保留。训练配方、损失掩码和超参数本身归于方法陈述，不应误标为评估结果。

Judge 接收类别、前提引用、推理、评估条件、不确定性和验证计划。它不再因“原文没有写出这个推论”机械拒绝合理分析，也不要求新设想已经有实验证明；仍须拒绝虚构数值、作者私下想法、无根据的泛化、概念偷换和把设想写成已验证事实。

若正文没有明确标注分析/设想边界，或某种分析没进入独立分类，则从已核验的论述重建回答，保留类别标签和不确定性。混合回答中的错误部分被移除时，其余合格分析和设想可以保留。可选响应字段 `statements` 保存通过检查的分类论述，已有 answer/evidence/reviews 接口仍兼容。

**`supported` 在这里是复核状态，不是客观真理、统计置信度或外部复现认证。** 引用可以支持分析前提，不能被误读为原论文已经证明了助手提出的新方案。

## 仍需保留的边界

开放研究不等于任意发挥。分析只能基于当前论文前提；未检索到某实验不等于全文从未做过该实验，证据缺失也不等于方法已被证伪。对作者内部真实想法仍不能推测为事实。

多项复杂实测仍返回覆盖不足或复核调整标记，不能据此宣称每个问题已完整回答。模型也仍可能误分类或漏判；类型化检查降低风险，但不替代研究者审阅和独立复现。初轮真实回答耗时约 53–254 秒，延迟和成本仍需后续优化。
