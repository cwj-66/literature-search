# 论文分析：故障问答与 GitHub 代码复用记录

调研与实现日期：2026-10-17。本文区分浏览器连接、后台任务、模型服务和分析质量，避免把所有失败归为“大模型坏了”。

## 问题与处理

| 问题 | 原因与判断方法 | 本项目处理 |
|---|---|---|
| 页面出现 `Failed to fetch`，是不是模型分析失败？ | 不一定。它表示浏览器没拿到可用响应，可能是断网、代理、跨域、连接被重置；后台任务可能继续执行。截图不能确定是哪一种网络原因。 | 已修复“一次轮询失败后停止更新”：自动重连，恢复联网或回到页面时主动查询；提示连接状态未知，不把网络错误标成模型任务失败。 |
| 提交时断线，能直接重发吗？ | 服务端可能已经创建任务，只是响应丢了；盲目重发可能重复计费。 | 自动恢复只做 GET 查询，不自动重复 POST。已有分析任务创建接口会复用同一论文的活动任务；同步工具路径不能据此宣称全链路幂等。 |
| 遇到 429 怎么办？ | RPM、TPM、服务容量、余额不足都可能表现为 429。 | 识别额度类错误码，额度不足直接提示；普通限流尊重 `Retry-After`、`retry-after-ms`，没有有效等待头时采用指数退避和随机抖动。超长等待直接结束本次尝试。 |
| 网络超时、连接重置、502/503 要不要重试？ | 这些通常是暂时故障。响应丢失不代表上游一定没处理，重试仍可能产生模型费用。 | 模型 HTTP 请求最多 3 次；重试网络传输错误、408/409/429 和 5xx；不重试任务全流程。 |
| 401/403、模型配置错误也重试吗？ | 相同配置重试不会修复权限、密钥或模型名。 | 不重试普通 4xx；分别提示权限、额度、HTTP 配置错误。服务端明确禁止重试时遵守该提示。 |
| 思考模式会占满输出吗？ | 已复现：8192 个 completion token 全用于 reasoning，正式内容为 0，结束原因为 `length`。 | 保留此前的修复：DashScope 结构化调用关闭显式思考；识别长度截断，不接收半截答案或思考文本冒充正式结果。 |
| 关闭思考后，正式结果仍超过输出上限怎么办？ | 结论与引文过多仍可能截断。 | 提取阶段遇到输出上限时将段落组二分，最多递归 3 层，保留原段落编号；无法继续拆分时明确失败，不无限重试。 |
| 输入超过上下文上限怎么办？ | 输入上限与输出上限是两种问题，增加输出额度不能解决输入过长。 | 识别上下文错误，提取阶段同样缩小输入；单个段落仍超限时终止。当前首次切分按字符估算，并不宣称是精确 token 计数。 |
| 多段都成功，但最后汇总超限怎么办？ | 合并后的候选结论可能再次超过输入或输出预算。 | 汇总超限时保留有原文依据的分段候选，按类别轮流取样、最多 60 项，然后继续逐项核对，明确提示可能未纳入全部内容；不把原始候选直接作为最终可信结论。 |
| 证据核对也超限怎么办？ | 审核输入仍可能过长。 | 自动把待核对结论分成两组分别核对。重复、遗漏、越界的审核编号仍判为失败，不擅自默认通过。 |
| 模型返回非 JSON、字段不符怎么办？ | `json_object` 只限制 JSON 语法，不能保证符合业务 Schema。 | 保留 Pydantic 校验与一次格式修复；第二次失败终止。无效输出不写成功结果，也不写提取断点。 |
| 第 7 段失败，前 6 段要重跑吗？ | 整篇重跑浪费时间和费用。 | 新增 SQLite 提取步骤缓存；键包含完整消息、模型名、提示版本的哈希。失败后重试复用已完成提取，之后仍重新做证据核对。成功后清理本次步骤；失败缓存最多保留 7 天，每库最多 500 条。 |
| 重启后是不是能自动从断点继续？ | 步骤缓存与完整工作流恢复不同。 | 既有恢复机制会将运行中任务标为重启中断，排队任务重新入队；用户重试时可复用步骤缓存。本次没有实现运行中任务自动恢复执行，也没有复用 LangGraph 的完整图快照协议。 |
| 多人同时分析会不会挤爆模型或机器？ | 请求并发、RPM、TPM、容器资源是不同限制。 | 模型调用每进程最多并发 2；已有单个后台分析队列保留。此限制不是跨进程限流，也不是准确的 TPM/RPM 额度控制。 |
| 会不会一直卡在“分析中”？ | 单次请求有超时，但多段与多次重试叠加后整篇耗时更长。 | 分析阶段总处理上限 15 分钟，超时后任务失败并允许重试；准备材料耗时另计。前端只查询，不依赖长连接来保活任务。 |
| 下载不到 PDF、扫描件没文字怎么办？ | 论文来源限流、付费墙、解析失败、纯图片 PDF 都可能导致全文不足。 | 沿用公开全文获取与摘要降级，并标明分析依据。上传 PDF 的 MinerU 解析属于另一条链路；不能把摘要分析显示为已阅读全文。 |
| 分析成功是否代表结论一定正确？ | 不代表。原文匹配也可能存在主体、否定、条件或指标理解错误。 | 沿用原文连续摘录校验、段落定位、数字核对与模型语义复核。没有证据的维度保留缺失，不补造实验数据；模型复核仍可能出错。 |
| 论文里藏有“忽略前文”等指令怎么办？ | 文档内容可能携带提示注入。 | 沿用材料数据边界与忽略文档指令的系统提示；模型没有因此获得执行系统命令的权限。提示隔离并非完美防护。 |

## 本次修改入口

- `backend/app/infrastructure/llm.py`：错误分类、最多 3 次请求、退避、服务端等待头、并发限制。
- `backend/app/services/analysis/evidence_analysis.py`：超限拆分、汇总降级、核对拆分、提取断点读写。
- `backend/app/services/analysis/checkpoints.py`：短期步骤缓存及成功后清理。
- `backend/app/services/analysis/analysis.py` 与 `backend/app/tools/analyze_paper.py`：分析上限、缓存作用域。
- `frontend/src/useAnalysisPolling.ts`、`frontend/src/pages/workspace/PaperReadPage.tsx`、`frontend/src/api.ts`：自动重连、错误分级、只恢复查询。
- `backend/tests/test_analysis_resilience.py`：13 项故障注入与恢复测试；结合既有相关测试共 52 项。

验证包括：429 等待、503/连接错误恢复、重试次数上限、401/额度错误不重试、限速配额与余额不足的区分、异常等待头、并发上限、超限二分与原文编号保留、核对拆分后判定不丢失、单段不可继续拆分、失败后断点复用、成功后清理、总处理时限。浏览器用模拟接口断线验证自动恢复、提示清除、不重复提交，以及 404 不无限重试；未用真实用户论文制造故障。

## 保留的边界与后续选项

1. 没有增加 Redis、Celery、跨机器租约或自动切换模型供应商。目前规模用现有队列和 SQLite 更容易维护。
2. 同步批量工具仍可能受浏览器、代理或 Cloudflare 的长请求上限影响；后续可改为工具调用创建任务并返回任务 ID，避免一次 HTTP 请求承载多篇深度分析。当前详情页的独立后台任务不依赖该长请求。
3. 浏览器网络故障不会向后台发送取消；离开页面只停止该页面的查询。
4. 超时后重试可能重复产生模型费用，当前没有模型供应商端的“恰好一次”保证。
5. 还没有按账户配置精确 token 限流，也没有自动依据各模型 tokenizer 计算上下文余量。
6. 若配置更换了模型行为、分析提示版本或权限边界，应同步调整缓存版本/范围。本缓存针对当前单实例文献库，没有引入多租户权限隔离机制。
