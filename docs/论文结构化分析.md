# 单篇论文内容分析与摘要提取

对应任务书的论文内容自动分析要求：用户在论文详情页触发分析，生成中文速读摘要，提取研究内容、技术方案和作者声称的创新点，并能查看每项结论的原文依据。

## 展示字段

| 字段 | 内容 |
| --- | --- |
| 中文速读摘要 | 问题、方法和主要结论，目标长度150至250字 |
| 论文类型 | 方法研究、实证研究、综述、理论研究、数据集或基准、系统研究；证据不足时未知 |
| 研究背景与核心问题 | 研究对象、已有工作的不足和本文目标 |
| 主要研究内容 | 逐项列出本文完成的研究工作 |
| 技术方案概述 | 输入、核心处理、输出，或相应的非算法研究设计 |
| 技术步骤或研究过程 | 按原文顺序展示步骤 |
| 创新点 | 作者声称的贡献，不代表系统独立验证其新颖性 |
| 实验或验证 | 结论，以及数据集或研究对象、比较对象、指标、结果和成立条件 |
| 局限与未来工作 | 只提取作者明确说明的内容 |
| 关键词 | 核心研究概念，保留必要的英文名称 |

缺失字段显示“提供的材料中未明确说明”，不等于整篇论文没有说明。综述和理论研究采用相应的分析方式，不要求虚构算法或数据集实验。

## 固定处理流程

1. 从允许访问的公开全文链接获取HTML或PDF，执行现有正文质量检查；获取失败时回退到摘要，并保存原因。本文分析不调用向量服务。
2. 对解析文本按章节和段落编号。段落编号仅用于定位本次提取的文本，不冒充PDF原始页码。参考文献独立成章时排除。
3. 短文本直接提取；长文本按预算依次提取，再合并候选结论。汇总保留原文摘录和原段落编号，不把第一轮摘要当作原文。
4. 模型输出结构化JSON，用Pydantic校验；格式失败只修复一次。逐项校验段落编号、原文摘录和数字来源，过滤无依据项。
5. 再调用模型核对摘录是否支持结论，包括数据集、比较条件、指标、否定语义和作者归属。核对输出缺失、重复或非法时任务失败；已有成功结果继续保留。
   如果概括性摘要未通过核对，但已有研究问题、内容或方法等通过核对，直接组合这些中文结论形成速读摘要并保留其原文引用，不新增事实，也不额外调用模型补写。材料稀少时不为凑字数扩写。
6. 将通过核对的结论、引用段落、输入文本SHA-256、模型、提示词版本、生成时间和覆盖范围持久化。重复查看使用已有结果，用户可重新分析。

全文输入有大小和页数限制，超出文本预算时选择部分章节并标注截取。前端分别显示“基于可获取的全文文本分析”“基于全文部分章节分析”“仅基于摘要分析”，并展示覆盖章节。图表、公式、扫描件及附录可能未完整解析，不能宣称已经读完全部材料。

## 接口兼容

沿用现有分析任务接口和SQLite结果表，新增信息存入JSON载荷，无需重建数据库。保留旧版字符串字段供已有调用方使用，增加 `summary`、`paper_type`、`claims`、`source_paragraphs`、`analysis_warnings`、`content_hash`。

每个claim包含种类、中文结论和原文引用；实验项可包含五个验证子字段。`supported`表示通过程序检查和模型支持性核对，不是人工确认或正确率保证。

旧版成功结果可继续查看；用户点击重新分析后生成新版结果，不自动批量重跑或产生模型费用。推荐功能仍使用兼容关键词字段，本次不调整推荐算法。

## 边界与后续验证

JSON校验、原文匹配和模型核对不能保证语义正确。应人工抽查方法论文、综述、理论论文、摘要模式及解析失败案例，重点核对创新点归属和实验数字对应关系。旧结果的生成时间、模型及提示词版本用于区分不同分析记录。

方案参考：[ChatPaper的分章节总结](https://github.com/kaixindelele/ChatPaper)、[PaperQA的证据收集与回答](https://github.com/Future-House/paper-qa)、[GROBID的学术PDF结构化解析](https://github.com/grobidOrg/grobid)。本项目采用固定流程，不引入完整Agent框架或新增GROBID服务。
